# ADDENDUM5 Q11 - Cierre del tope ante ERROR_DATOS / 0 dias validos (fila B2). Texto para congelar; vigente desde la fecha de congelacion, antes de que cualquier ejecucion ocurra con fecha UTC >= 2027-01-01.

Ningun veredicto emitido hasta hoy cambia (todos son anteriores a 2027-01-01). Sustituye SOLO la fila B de ADDENDUM4 sec. 4 (tabla SOL013/P-A/P-B/P-C y tabla thru1); F, G y el resto quedan intactos. Referencias de ADDENDUM4 usadas: sec. 4 (tabla), sec. 5(b) y (b2) (la tabla de A4 dice "sec. 6 b": es 5(b)).

## 1. Tabla SOL013 / P-A / P-B / P-C (primera fila que se cumpla; A y C-H como en ADDENDUM4)
A  terminal ya emitido => se mantiene (5(b)); si hay ERROR_DATOS se anota y no se reescribe estado (5(b1)).
B  (ERROR_DATOS o nvalid = 0) y fecha de ejecucion UTC < 2027-01-01 => INSUFFICIENT (no cuenta ningun dia nuevo; no escribe estado). Sin cambio.
B2 (ERROR_DATOS o nvalid = 0) y fecha de ejecucion UTC >= 2027-01-01 => CERRADO_INSUFFICIENT (terminal; SE ESCRIBE el estado). Campos del terminal: fecha, nd = last_nd del estado cargado (0 si no hay), causa = ERROR_DATOS | SIN_DIAS_VALIDOS, motivo (primeros mensajes de error), nd_ficheros, en_revision.
nvalid = 0 significa 0 dias con dec2_D y dec3s100_D canonicos dentro de [desde, 2026-12-31] (el D_AB vacio con nvalid > 0 NO es B2: lo cierra F).
nd_ficheros = numero de dias D, desde <= D <= 2026-12-31, con ambos ficheros canonicos presentes, contado SOLO por nombre de fichero (sin leer ni calcular ningun resultado).
en_revision = true siempre que la causa sea ERROR_DATOS, o que nd_ficheros >= 20; con en_revision, el informe imprime SIEMPRE "CERRADO_INSUFFICIENT [EN REVISION]" (tambien en ejecuciones posteriores, via la fila A: el marcador se persiste en el terminal).
Por que no basta "last_nd < 20": si el error empezo antes de que se acumularan 20 dias, last_nd (la ultima evaluacion valida) infravalora los dias realmente disponibles; B2 cierra igual (es el terminal menos comprometedor: sin promocion y sin REFUTED), pero lo declara cierre ADMINISTRATIVO, no evidencia de nada: no puede citarse a favor ni en contra de la hipotesis.

## 2. Tabla thru1 (por brazo; primera fila que se cumpla; A, C-H como en ADDENDUM4)
A  terminal del brazo ya emitido => se mantiene (+ aviso/EN REVISION si hay error).
B  fecha < 2027-01-01 y cualquiera de: sha de codigo/modelo distinto del registrado; ERROR_DATOS de insumos; aceptacion sobre quemados no pasada/obsoleta; 0 dias validos (incluye 0 tras la condicion de rasgo PC_AS); ERROR_DATOS de Chainlink (solo brazo PC_AS) => INSUFFICIENT, parada hasta corregir, sin escribir estado. Sin cambio de fondo (el prereg ya lo exigia; ADDENDUM4 solo nombraba sha y ERROR_DATOS).
B2 fecha >= 2027-01-01 y cualquiera de las causas de B => para CADA brazo sin terminal (el de Chainlink: solo PC_AS): CERRADO_INSUFFICIENT con los campos de la sec. 1 (nd = last_nd del brazo, 0 si no hay; nd_ficheros = dias candidatos con RT_D en toxicidad_thru1 y redteam, por nombre; en_revision = true). Esta fila sustituye, solo para esta fecha, la linea "Parada: sha ... distinto => INSUFFICIENT hasta corregir" del prereg y la excepcion "no escribe estado".
El checkpoint (filas C-F) sigue evaluandose ANTES de B2 solo cuando los datos son evaluables; con una salida temprana de B no se evalua checkpoint alguno.

## 3. Reapertura de un B2 (unica via, sin automatismo)
Un terminal B2 solo se anula por correccion de un bug del evaluador (o del dato, si el defecto es un fichero no canonico / filas de otro dia reparado SIN alterar el contenido de dec2/dec3s100 de ningun dia) anotada en DECISION_LOG con sha, y decidida por escrito ANTES de ejecutar la reevaluacion (ADDENDUM4 5(b2)). La reevaluacion aplica la tabla de ADDENDUM4 a los dias <= 2026-12-31 y NUNCA puede emitir CONFIRMA_FINAL, CANDIDATO ni PROMOCION (racha y checkpoints exigen evaluaciones sucesivas): solo REFUTA, REFUTED o CERRADO_INSUFFICIENT. Asi un ERROR_DATOS persistente no puede usarse para evitar un REFUTED, y reabrir nunca puede fabricar una confirmacion.

## 4. Lo que este addendum NO cierra (declarado)
(a) Estado JSON ilegible/corrupto: cargar_estado lanza excepcion (fail-closed) y el evaluador solo avisa; no hay terminal. Requiere accion humana (no se sobrescribe un posible terminal). (b) Que el evaluador no se ejecute (cron parado): exige vigia que avise si lleva >= 2 dias sin ejecutarse. (c) Dias > 2026-12-31 con datos defectuosos no se cargan y no afectan.
